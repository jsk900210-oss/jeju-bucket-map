# 백엔드 작업 정리

## 현재 확인된 작업

- POI 데이터를 이용한 장소 검색
- 숙소 근처 혼밥 가능 식당 추천
- 가까운 편의점 검색
- 장소까지의 거리 계산
- `solo_friendly` 값을 이용한 혼자 이용 가능 여부 판단
- RAG 검색 결과와 추천 답변 생성

## 확인된 문제

- 관광지 질문에 음식점과 편의점이 추천되는 문제
- 편의점 질문에 음식점이 함께 추천되는 문제
- 현재 데이터에 약국과 관광지 POI가 부족한 문제
- 데이터에 없는 정보를 사실처럼 답할 가능성
- 검색 결과의 카테고리 필터가 정확하지 않은 문제

## 앞으로 진행할 작업

- 질문에 맞는 카테고리만 검색하도록 필터 수정
- 음식점·편의시설·관광지·약국 카테고리 분리
- 검색 결과가 없을 때 `확인 가능한 정보가 없습니다`라고 응답
- 근거가 되는 `poi_id`와 장소 정보를 답변에 함께 기록
- 추천 결과의 거리와 혼자 이용 가능 여부 검증
- 프론트엔드에서 사용할 API 규격 작성

## 사용자 계정 관리

- 사용자 인증에는 Google OAuth를 사용합니다.
- 서비스는 비밀번호와 Google 인증 계정을 직접 관리하지 않습니다.
- 최초 로그인 시 Google에서 제공받은 식별 정보를 기준으로 내부 사용자 계정을 생성합니다.
- 이후 모든 서비스 기록은 내부 사용자 ID를 기준으로 관리합니다.

관리 대상:

- 사용자 프로필
- Join 생성 내역
- Join 신청 내역
- Join 취소 내역
- 실제 참여 기록

Google은 로그인과 사용자 인증을 담당하고, 서비스 백엔드는 사용자 활동 기록을 관리합니다.

## 평가 데이터

백엔드 검색과 추천 품질을 확인하기 위해 다음 평가 자료를 관리합니다.

| 구분 | 수량 | 포함 내용 |
| --- | ---: | --- |
| 정보 QA | 20개 | 질문, 정답, 근거, 합격 기준 |
| 매칭 골드셋 | 15개 | 사용자 조건, 기대 추천, 선정 이유 |
| 함정 질문 | 8개 | 위험·허위 유도 질문, 기대 대응 |
| 합계 | 43개 | 팀원 최종 검수 및 라벨링 |

AI가 작성한 내용은 초안으로만 사용합니다. 최종 질문, 정답, 근거와 합격 기준은 팀원이 직접 검토하고 라벨링합니다.

## 권장 작업 순서

1. 장소 카테고리 검색 오류 수정
2. Google OAuth와 내부 사용자 계정 구조 설계
3. Join 생성·신청·취소 API 구현
4. 프론트엔드 로그인 및 사용자 화면 연결
5. 평가 데이터 43개 팀원 검수
6. 전체 기능 테스트
